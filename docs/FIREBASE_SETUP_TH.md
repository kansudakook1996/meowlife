# คู่มือตั้งค่า Firebase (บัญชีผู้ใช้ + ซิงก์ข้อมูล)

> **สถานะ (2026-10-28)**: Project `meowlife-c1657` สร้างแล้ว / ใส่ config ในแอปแล้ว (ขั้นที่ 6) /
> แอปมีหน้า "บัญชีออนไลน์ (ทดลอง)" สำหรับล็อกอินและทดสอบการเชื่อมต่อแล้ว (ขั้นที่ 7) /
> ตรวจจากภายนอกแล้วว่า Firestore ปฏิเสธคนที่ไม่ได้ล็อกอิน (HTTP 403) /
> **ยังไม่ได้ทดสอบล็อกอินจริง** — เจ้าของต้องสร้างบัญชีเองในแอป / การซิงก์ข้อมูลรายรับรายจ่ายยังไม่ได้ทำ (M4)
> ผมจะไม่ขอรหัสผ่านหรือ Secret ใด ๆ จากคุณ

## ภาพรวม
- **Firebase Authentication** = ระบบล็อกอิน (อีเมล/รหัสผ่าน)
- **Cloud Firestore** = ฐานข้อมูลบนคลาวด์ ใช้ซิงก์ข้ามเครื่อง
- **Security Rules** = กฎที่บอกว่าใครอ่าน/เขียนอะไรได้ — สำคัญที่สุด เพราะค่า config ของแอปเป็นข้อมูลสาธารณะ

## ค่าใช้จ่าย (อ่านก่อน)
- แผน **Spark** ไม่ต้องผูกบัตรเครดิต มีโควตาฟรีต่อวัน เมื่อเกินโควตาจะหยุดทำงานชั่วคราว ไม่เก็บเงิน
- แผน **Blaze** จ่ายตามใช้ ต้องผูกบัตร — **ยังไม่ต้องใช้** สำหรับแอปส่วนตัว
- โควตาเปลี่ยนได้ ตรวจล่าสุดที่ https://firebase.google.com/pricing ก่อนตัดสินใจทุกครั้ง
- ผมไม่รับประกันว่าฟรีตลอดไป ถ้าเงื่อนไข Google เปลี่ยน ให้ตรวจหน้า pricing

## ขั้นที่ 1 — สร้าง Firebase Project
1. **เป้าหมาย**: สร้าง "โปรเจกต์" ที่เก็บ Auth และฐานข้อมูลของ MeowLife
2. **URL**: https://console.firebase.google.com/ (ล็อกอินด้วยบัญชี Google ของคุณเอง)
3. **กด**: **Create a project** (หรือ "เพิ่มโปรเจกต์")
4. **ค่าที่กรอก**
   - ชื่อโปรเจกต์: `meowlife` (ระบบอาจเติมตัวเลขต่อท้ายเป็น Project ID เช่น `meowlife-1a2b3`)
   - Google Analytics: **ปิด** (ไม่จำเป็น และลดข้อมูลที่ส่งออก)
   - ถ้าถามเรื่อง Gemini/AI assistance: เลือกตามสะดวก ไม่กระทบแอป
5. **ผลที่ควรเห็น**: หน้า Project Overview ของ `meowlife`
6. **ทดสอบ**: มุมซ้ายบนแสดงชื่อโปรเจกต์
7. **ปัญหาที่พบบ่อย**: ชื่อซ้ำ → ใช้ชื่ออื่น เช่น `meowlife-kansu`
8. **ความปลอดภัย**: บัญชี Google ที่ใช้ควรเปิด 2-Step Verification

## ขั้นที่ 2 — ลงทะเบียนแอป (Web app)
1. **เป้าหมาย**: ได้ค่า config ที่แอปใช้เชื่อมต่อ
2. **ที่**: หน้า Project Overview → กดไอคอน **`</>`** (Web)
3. **ค่าที่กรอก**: App nickname = `MeowLife Desktop` / **ไม่ต้อง**ติ๊ก Firebase Hosting
4. **กด**: **Register app**
5. **ผลที่ควรเห็น**: โค้ดตัวอย่างที่มี `firebaseConfig = { apiKey: "...", authDomain: "...", projectId: "...", ... }`
6. เก็บหน้านี้ไว้ (ดูย้อนหลังได้ที่ ⚙️ Project settings → General → Your apps)
7. **ปัญหา**: ปิดหน้าไปแล้ว → เข้า Project settings ดูได้เสมอ
8. **ความปลอดภัย**: ค่า `apiKey` ของ Web app **ไม่ใช่ความลับ** (อยู่ในแอปทุกตัว) แต่
   **ห้าม** ดาวน์โหลด/ใช้ "Service account private key" (ไฟล์ JSON ใน Project settings → Service accounts) กับแอปนี้เด็ดขาด

## ขั้นที่ 3 — เปิด Authentication แบบอีเมล/รหัสผ่าน
1. **เป้าหมาย**: ให้ผู้ใช้สร้างบัญชีและล็อกอินในแอป
2. **ที่**: เมนูซ้าย **Build → Authentication** → **Get started**
3. **กด**: แท็บ **Sign-in method** → **Email/Password** → เปิด **Enable** (อันแรก) → **Save**
4. **ค่าที่เลือก**: Email link (passwordless) ปิดไว้ก่อน
5. **ผลที่ควรเห็น**: Email/Password แสดงสถานะ **Enabled**
6. **ทดสอบ**: แท็บ **Users** → **Add user** สร้างผู้ใช้ทดสอบได้ (ใช้อีเมลทดสอบ ไม่ต้องเป็นอีเมลจริง)
7. **ปัญหา**: ไม่เห็นเมนู → เลือกโปรเจกต์ให้ถูกที่มุมซ้ายบน
8. **ความปลอดภัย**: แท็บ Settings → **User actions** พิจารณาปิด "Enable create (sign-up)" ถ้าต้องการให้มีแค่บัญชีคุณ

## ขั้นที่ 4 — สร้าง Cloud Firestore
1. **เป้าหมาย**: สร้างฐานข้อมูลบนคลาวด์
2. **ที่**: **Build → Firestore Database** → **Create database**
3. **ค่าที่เลือก**
   - Edition/Mode: ถ้ามีให้เลือก ใช้ค่ามาตรฐาน (Standard)
   - **Location**: เลือกภูมิภาคที่ใกล้ไทยที่สุดที่มีให้ เช่น `asia-southeast1 (Singapore)` —
     **เลือกแล้วเปลี่ยนไม่ได้**
   - Security rules: เลือก **Start in production mode** (ปิดทุกอย่างไว้ก่อน)
   - ❌ อย่าเลือก test mode — มันเปิดให้ทุกคนอ่าน/เขียนได้ 30 วัน
4. **ผลที่ควรเห็น**: หน้า Data ว่าง ๆ
5. **ทดสอบ**: แท็บ Rules แสดง `allow read, write: if false;`
6. **ปัญหา**: ระบบให้เปิด billing → ตรวจว่าเลือกแผน Spark / ฐานข้อมูลแบบ default
7. **ค่าใช้จ่าย**: อยู่ในโควตาฟรีของ Spark สำหรับการใช้งานส่วนตัวทั่วไป (ตรวจหน้า pricing)

## ขั้นที่ 5 — ตั้ง Security Rules
1. **เป้าหมาย**: ให้แต่ละคนเห็นเฉพาะข้อมูลของตัวเอง (`users/{uid}/...`)
2. **ที่**: Firestore Database → แท็บ **Rules**
3. **ทำ**: เปิดไฟล์ `firestore.rules` ในโปรเจกต์ คัดลอกทั้งหมดไปวางแทน → **Publish**
4. **ผลที่ควรเห็น**: "Rules published"
5. **ทดสอบ**: แท็บ Rules → **Rules Playground**
   - Location: `/users/abc/transactions/t1`, Simulation type: get
   - Authenticated: เปิด, Firebase UID: `abc` → ✅ Allowed
   - เปลี่ยน UID เป็น `xyz` → ❌ Denied
   - (ในขั้น M4 จะมีเทสต์อัตโนมัติด้วย Firestore Emulator เพิ่ม)
6. **ปัญหา**: Publish ไม่ได้เพราะ syntax → ตรวจว่าคัดลอกครบทุกบรรทัด
7. **ความปลอดภัย**: ห้ามใช้ `allow read, write: if true;` ในระบบจริง

## ขั้นที่ 6 — ใส่ค่า config ในแอป ✅ ทำแล้ว
1. **เป้าหมาย**: บอกแอปว่าต้องเชื่อมกับ Firebase project ไหน
2. ค่าจากขั้นที่ 2 อยู่ในไฟล์ **`.env`** ที่โฟลเดอร์ `C:\dev\meowlife` (ชื่อตัวแปรขึ้นต้นด้วย `RENDERER_VITE_FIREBASE_`)
3. **ทำไมไฟล์นี้ขึ้น GitHub ได้**: ค่า config ของ Web app เป็นข้อมูลสาธารณะ (ฝังอยู่ในทุกแอปที่ใช้ Firebase)
   และตัวติดตั้งที่ GitHub สร้างให้ต้องมีค่านี้ถึงจะเชื่อมต่อได้ ความปลอดภัยมาจาก Auth + Security Rules
4. ถ้าอยากลองกับ Project อื่นเฉพาะเครื่องตัวเอง: สร้าง `.env.local` (ไม่ขึ้น GitHub) ใส่ตัวแปรชื่อเดียวกัน ค่านี้จะทับ `.env`
5. แก้ค่าแล้วต้อง build ใหม่ (`npm run dev` หรือ `npm run dist`)
6. ❌ ห้ามใส่ Service account key, รหัสผ่าน หรือ Token ในไฟล์ `.env` เด็ดขาด
7. (แนะนำ ไม่บังคับ) จำกัดการใช้ API key ได้ที่ https://console.cloud.google.com/apis/credentials →
   เลือก key "Browser key (auto created by Firebase)" → **API restrictions** → เลือกเฉพาะ
   Identity Toolkit API, Token Service API, Cloud Firestore API → Save

## ขั้นที่ 5 (อีกครั้ง) — Publish Rules เวอร์ชันล่าสุด ⚠️ ต้องทำ
`firestore.rules` มีการเพิ่ม collection `meta` สำหรับปุ่มทดสอบการเชื่อมต่อ ให้คัดลอกไฟล์ทั้งไฟล์ไปวางที่
Firestore Database → Rules → **Publish** อีกครั้ง (ไม่งั้นขั้นที่ 7 จะขึ้น permission-denied)

## ขั้นที่ 5 (ครั้งที่ 3) — Publish Rules ที่เข้มขึ้นสำหรับ 0.2.0 ⚠️ ต้องทำก่อนใช้ซิงก์เต็มรูปแบบ
กฎชุดนี้ตรวจ "ทุกฟิลด์" ของเอกสาร (ชนิดข้อมูล ความยาว ห้ามมีฟิลด์แปลกปลอม) แทนกฎเดิมที่จำกัดขนาดไม่ได้จริง
ทดสอบกับ Firestore Emulator แล้ว (`npm run test:rules` ผ่าน 10 ข้อ รวมเอกสารที่แอปสร้างจริง)
1. เปิดไฟล์ `firestore.rules` คัดลอกทั้งไฟล์ → Firebase Console → Firestore Database → Rules → วางแทน → **Publish**
2. ถ้า Publish แล้วซิงก์ขึ้น `permission-denied` ให้บอกผมพร้อมข้อความที่แอปแสดง (ห้าม Publish กลับเป็น `if true`)
3. ทดสอบกฎด้วยตัวเองบนเครื่องได้: ติดตั้ง Java 21 (`winget install Microsoft.OpenJDK.21`) แล้วรัน `npm run test:rules`

## ขั้นที่ 5 (ครั้งสุดท้าย) — Publish Rules แบบผ่อนคลาย ⚠️

0.4.0 เพิ่ม 3 คอลเลกชัน (credit_cards, card_charges, card_plans) คัดลอก `firestore.rules` ทั้งไฟล์ไป Publish ใหม่ (วิธีเดียวกับครั้งก่อน)

## ขั้นที่ 5 (ครั้งที่ 4) — Publish Rules สำหรับ 0.3.0 (Personal Portal) ⚠️
0.3.0 เพิ่ม 6 คอลเลกชัน (tasks, journal_entries, goals, habits, habit_checks, notes) ต้องคัดลอก `firestore.rules` ทั้งไฟล์ไป Publish ใหม่
- ถ้ายังไม่ Publish: รายการรับ-จ่ายยังซิงก์ได้ปกติ แต่แถบสถานะจะขึ้น "ซิงก์ไม่สำเร็จ" พร้อมข้อความ permission-denied (ตารางที่ถูกปฏิเสธไม่ขวางตารางอื่น)
  ข้อมูลโมดูลใหม่ยังอยู่ในเครื่องครบ และจะซิงก์เองหลัง Publish
- ตรวจผล: ซิงก์แล้วดูที่ Firestore → Data → `users/{uid}/` ต้องเห็นคอลเลกชันใหม่ (เมื่อมีข้อมูล)

## ซิงก์ข้อมูลรายรับรายจ่าย (0.2.0)
- เมื่อเข้าสู่ระบบ แอปสำเนาข้อมูลของคุณไปที่ `users/{uid}/transactions|categories|payment_methods|recurring_rules`
  ดูได้ที่ Firebase Console → Firestore → Data (ข้อมูลการเงินของคุณจะอยู่บนเซิร์ฟเวอร์ Google ในบัญชีของคุณเอง ไม่ได้เข้ารหัสฝั่งแอป)
- ฐานข้อมูลในเครื่องผูกกับบัญชีแรกที่ซิงก์ ถ้าจะเปลี่ยนบัญชีบนเครื่องเดิม ให้สำรองข้อมูลแล้วติดตั้งใหม่/ล้างข้อมูลก่อน (แอปจะบอกเมื่อพบกรณีนี้)
- ค่าใช้จ่าย: การซิงก์ปกติใช้การอ่าน/เขียน Firestore หลักสิบถึงหลักร้อยครั้งต่อวันสำหรับการใช้ส่วนตัว อยู่ในโควตาฟรี Spark
  (ตรวจโควตาปัจจุบันที่ https://firebase.google.com/pricing) ดูการใช้งานจริงได้ที่ Console → Usage
- ทดสอบ 2 เครื่อง: ติดตั้งแอปเครื่องที่สอง → เข้าสู่ระบบด้วยบัญชีเดียวกัน → ข้อมูลจะมาเองภายในไม่กี่วินาที
  ลองปิดเน็ตเครื่องหนึ่ง เพิ่มรายการ แล้วเปิดเน็ต ดูแถบสถานะซิงก์ล่างเมนูซ้าย

## ขั้นที่ 7 — สร้างบัญชีและทดสอบการเชื่อมต่อ (เจ้าของทำเอง)
1. **เป้าหมาย**: ยืนยันว่าแอปล็อกอินได้ เขียน/อ่านข้อมูลของตัวเองได้ และอ่านของคนอื่น**ไม่ได้**
2. เปิดแอป: ใช้แอปที่ติดตั้งไว้ (อัปเดตเป็น **0.1.4 ขึ้นไป** ก่อน — แอปจะแจ้งเองว่ามีเวอร์ชันใหม่)
   หรือรัน `npm run dev` จากโฟลเดอร์โปรเจกต์
3. เมนู **ตั้งค่า** → การ์ด **☁️ บัญชีออนไลน์ (ทดลอง)**
4. ใส่อีเมลของคุณและรหัสผ่านใหม่ (อย่างน้อย 6 ตัว ไม่ควรซ้ำกับรหัสอื่น) → กด **สร้างบัญชีใหม่**
   - ครั้งต่อไปใช้ **เข้าสู่ระบบ** — แอปจำการล็อกอินไว้ ปิดเปิดแอปแล้วยังอยู่
5. กด **ทดสอบการเชื่อมต่อ** → ผลที่ควรเห็น 4 บรรทัด
   | ผล | ความหมาย |
   |---|---|
   | ✓ เข้าสู่ระบบ | Firebase Authentication ใช้งานได้ |
   | ✓ บันทึกข้อมูลของฉัน | เขียน `users/{uid}/meta/connection` ได้ |
   | ✓ อ่านข้อมูลของฉัน | อ่านกลับมาได้ตรงกัน |
   | ✓ กันคนอื่นอ่านข้อมูล | Security Rules ปฏิเสธการอ่านของผู้ใช้อื่นถูกต้อง |
6. ตรวจใน Console ได้อีกทาง: Authentication → Users จะเห็นอีเมลของคุณ /
   Firestore → Data จะเห็น `users → (uid) → meta → connection`
7. **ข้อผิดพลาดที่พบบ่อย**: ดูตารางขั้นที่ 8 (แอปแสดงข้อความภาษาไทยพร้อมบอกว่าต้องกลับไปแก้ขั้นไหน)
8. **ความปลอดภัย/ค่าใช้จ่าย**: ทดสอบ 1 ครั้งใช้การอ่าน/เขียน Firestore ไม่กี่ครั้ง อยู่ในโควตาฟรี Spark สบาย ๆ
   รหัสผ่านพิมพ์ในแอปเท่านั้น แอปไม่บันทึกรหัสผ่านลงไฟล์หรือ log

## ขั้นที่ 8 — แก้ปัญหา `permission-denied` และอื่น ๆ
| ข้อความในแอป / อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
